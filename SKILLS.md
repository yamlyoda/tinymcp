# SKILLS — Инцидентный MCP-сервер для агента дежурного инженера (on-call)

## Назначение

MCP-сервер, предоставляющий набор **доменных tools** для агента дежурного
инженера (on-call). Сервер позволяет агенту искать и просматривать инциденты,
деплои, логи, метрики, runbook-и и карточки сервисов, а также выполнять
операции изменяющего характера (подтверждение инцидента, сохранение сводки).

## Стек технологий

| Компонент       | Технология         |
|-----------------|--------------------|
| Фреймворк MCP   | FastMCP            |
| Язык            | Python 3.12        |
| Менеджер пакетов| uv                 |
| Проверка        | MCP Inspector      |

> **Важно:** тесты и технологии изменять нельзя. Стек фиксирован.

## Набор tools

### Read-tools (только чтение, без side effects)

| № | Имя tool               | Аргументы                                                                 | Описание |
|---|------------------------|---------------------------------------------------------------------------|----------|
| 1 | `incidents_search`     | `service` (str), `severity?` (str), `status?` (str), `time_range?` (str)  | Поиск инцидентов по сервису, severity, статусу и временному диапазону. |
| 2 | `incident_get`         | `incident_id` (str)                                                       | Карточка одного инцидента по его ID. |
| 3 | `deploys_recent`       | `service` (str), `limit?` (int)                                           | Последние деплои сервиса (по умолчанию — последние 10). |
| 4 | `logs_query`           | `service` (str), `time_range` (str), `query?` (str), `level?` (str)       | Поиск по app_logs: текстовый запрос и/или фильтр по уровню логирования. |
| 5 | `metrics_latency`      | `endpoint` (str), `time_range` (str), `bucket?` (str)                     | Агрегат по request_logs: число запросов, avg, p95, доля попаданий в кэш по временным корзинам. Без этого tool агент не увидит форму деградации. |
| 6 | `runbook_get`          | `service` (str)                                                           | Runbook сервиса из `homework-stand/runbooks/<service>.md`. |
| 7 | `service_catalog_get`  | `service` (str)                                                           | Карточка сервиса: team, on-call, зависимости. |

### Write-tools (меняют состояние, отдельно от read)

| № | Имя tool                  | Аргументы                          | Описание |
|---|---------------------------|------------------------------------|----------|
| 1 | `incident_acknowledge`    | `incident_id` (str)                | Переводит инцидент в статус `acknowledged`. **Операция меняет состояние в БД.** |
| 2 | `incident_create_summary` | `incident_id` (str), `summary` (str) | Сохраняет сводку разбора в `incidents.summary`. **Операция меняет состояние в БД.** |

> В `description` каждого write-tool явно указано, что операция меняет
> состояние в БД — это единственный способ отличить её от чтения для модели.

## Требования к качеству tools

1. **title и description.** У каждого tool есть `title` и `description`,
   отвечающие на три вопроса:
   - **Что делает** — назначение tool;
   - **Когда применять** — сценарий использования;
   - **Ограничения / side effects** — что может пойти не так, есть ли побочные эффекты.

2. **Валидация аргументов.** Аргументы валидируются через `inputSchema`
   (в FastMCP — из аннотаций типов / Pydantic). Невалидные аргументы
   возвращают понятную ошибку до выполнения SQL.

3. **Структурированные ошибки.** Ошибки исполнения возвращаются структурированно
   (`isError: true`, понятный текст), чтобы агент мог сам исправить вызов,
   а не уронить сессию.

4. **Уникальные namespaced-имена.** Имена уникальны и namespaced:
   `incidents_*`, `incident_*`, `deploys_*`, `logs_*`, `metrics_*`,
   `runbook_*`, `service_*`.

5. **Доменные tools.** Tools доменные, а не универсальные: никакого
   `query(sql)` по всей базе. Каждый tool отвечает за один шаг разбора и
   сам решает, какой SQL выполнить.

## Проверка в MCP Inspector

Сервер проверяется в MCP Inspector:
- Read-tools вызываются и возвращают данные без изменения состояния БД;
- Write-tools вызываются и изменяют состояние (подтверждение, сводка);
- Невалидные аргументы возвращают `isError` с понятным текстом;
- Имена tools соответствуют namespacing-правилам.
